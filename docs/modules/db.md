# db

## Purpose

Postgres access through sqlx, plus the schema migrations in `crates/db/migrations/`. Queries use runtime-checked `sqlx::query` so builds never need a live database.

## Sub-docs

| Doc | Covers |

## Public API

- `MIGRATOR`: embedded migrations.
- `DatabaseUrl`: the connection URL held as a `Secret` (no `Debug`/`Display`/`Serialize`). `from_env()`/`from_lookup()` read `DATABASE_URL` (`DATABASE_URL_ENV`): absent is `None`; empty, non-UTF-8 or malformed (not a `postgres://`/`postgresql://` URL that sqlx can parse) is an error at load time naming the variable, never the value. `new(Secret)` applies the same URL check. `redactor()` removes the URL and its password (raw and percent-decoded, userinfo or `password=` query) from error text; apply it before logging any database error.
- `connect(&DatabaseUrl)`: opens a connection pool.
- `migrate(&pool)`: applies pending migrations.
- `PgPool`: re-exported pool type.
- `brightdata_runs`: queries for the Bright Data run tables, with plain row types (`RunRow`, `NewRunRow`, `RunPatch`, `SafetySettings`, `GateCounts`, `RunCaps`) so `db` needs no adapter types. Timestamps cross as epoch milliseconds; JSON as text.
  - `safety_settings` / `set_safety_settings`: the single settings row (`None` when missing; callers fail closed).
  - `gate_counts`: the tenant's runs and items since a day start, and whether the scope has an active run.
  - `insert_run_capped`: one transaction that takes `pg_advisory_xact_lock(hashtext(tenant_id))`, re-checks runs/day, items/run and items/day, then inserts; the partial unique index maps to `InsertRunError::ActiveRun`.
  - `update_if_active`: changes a run only while it is `starting`/`running`/`ready`, so a terminal status is never overwritten.
  - `load_run`, `active_runs`.
  - `insert_access_event` / `access_counts_by_host`: per-URL access outcomes (`ok`, `blocked_needs_kyc`, `skipped_robots`, `failed`) and their per-host totals.
  - `try_driver_lock`: session advisory lock on a dedicated connection (`DriverLock`); the worker holding it drives runs and runs start-up recovery.
- `access::PgAccessCounts(PgPool)`: implements `app::AccessCountsRepo` over `access_counts_by_host`; errors become `app::RepoError::Unavailable` with no detail and no logging (callers log a fixed message).
- `price_history`: matches and price observations, with plain row types (`NewObservation`, `ObservationRow`, `MatchRow`). Timestamps cross as epoch milliseconds; money as centavos.
  - `insert_observation`, `observations_since(retailer, sku, since_ms)` (sorted by `observed_at`, then `id`).
  - `upsert_match`: inserts or replaces the listing's match, except that a stored `rejected` match is never overwritten (a reviewer's decision wins); returns the rows written (1, or 0 when a rejection was kept), which `PgMatches` maps to `app::UpsertOutcome::{Written, KeptRejected}`. `match_status` reads one status.
  - `accepted_listings(asin)`: the `(retailer, retailer_sku)` pairs with an `accepted` match to that ASIN, sorted by retailer then SKU.
  - Adapters `PgPriceHistory(PgPool)` (implements `app::PriceHistoryRepo`) and `PgMatches(PgPool)` (implements `app::MatchRepo`). Errors become `app::RepoError::Unavailable` with no detail; stored text that fails domain validation is also `Unavailable`.
- `queue` (pgmq, ADR 0011): `Queue { SearchJobs, SearchJobsDlq, RefreshJobs, RefreshJobsDlq }` is a closed enum, so queue names never come from callers; `dead_letter()` gives a work queue's DLQ. Functions: `send(executor, queue, json)` (any executor, so it can join a caller's transaction), `read(pool, queue, vt_secs, qty) -> Vec<QueueMessage { msg_id, read_ct, message }>`, `delete`, `set_vt`, `dead_letter(pool, queue, msg_id, body)` (send to the DLQ and delete in one transaction; `DeadLetterError::NoDeadLetterQueue` for a DLQ) and `length`.
- `searches`: `create_search` (inserts the `searches` row and sends its `search_jobs` message in **one transaction**), `load_search`, `mark_running`, `finish` (only from `queued`/`running`: a terminal status never changes), `upsert_retailer_outcome`, `upsert_result`, `load_view(pool, tenant, id)` (tenant-scoped: another tenant's id reads `None`) and `view_from_rows` (`hidden_results` is always 0 here; membership filtering happens in `app::SearchResults`). Result rows carry `availability` and `membership_required`. `recent_results(pool, tenant, since_ms, title_contains, listing, limit)`: results of the tenant's searches since a time, one row per listing (its newest occurrence), newest first; the title filter is a case-insensitive plain-text match (`strpos`, so `%`/`_` are not wildcards). `PgSearches::new(pool, Arc<dyn app::Clock>)` implements `app::SearchRepo` (including `recent_results`, used by `app::TrackedOffers`).
- `users` (ADR 0012): `create_user` (duplicate e-mail → `CreateUserRowError::EmailTaken`), `find_credentials(email)` (the only read of `password_hash`), `find_by_id`, `set_memberships` (also sets `onboarded`), `set_locale`, `set_plan` (operator/seed use) and `record_from_row`, which fails closed (`None`) on any row breaking an invariant, including a tenant other than `user-<id>`. `PgUsers::new(pool, Arc<dyn app::Clock>)` implements `app::UserRepo`; errors carry no detail. Every query is keyed by user id or normalized e-mail.
- `sessions` (ADR 0012): opaque session records for the API's tower-sessions store: `insert_new` (`false` on an id collision), `save` (upsert), `load(id, now_ms)` (never returns an expired row), `delete`, `delete_expired(now_ms)`.
- `tracking`: `track(retailer, sku, now_ms)` (on conflict do nothing), `due(limit, older_than_ms)` (never-refreshed first, then oldest `last_refreshed_at`, then retailer, SKU), `mark_refreshed`.
- `usage`: `try_consume(pool, tenant, day_start_ms, n, cap) -> ConsumeOutcome { Granted, KillSwitch, CapReached }` reads `safety_settings.global_kill_switch` (`FOR SHARE`; a missing row counts as on) and takes the requests with a conditional upsert on `provider_usage`, so concurrent callers never exceed the cap. Also `used` and `day_start` (UTC). `PgRequestBudget::new(pool, clock, cap_per_day)` implements `app::RequestBudget`; database errors become `BudgetError::Unavailable`, so callers fail closed.
- `assistant` (ADR 0013): `used_on`/`add_usage` (atomic upsert-add on `agent_token_usage`, keyed by tenant and UTC day as days since 1970-01-01), `create_suggestion`, `suggestions_for_chat` (oldest first), `suggestion` (tenant-scoped), `decide` (upsert per tenant and listing, recording `decided_by_user_id`, `suggestion_id` and `decided_at`), `decisions_for_asin` and `decisions_for_listings`. `PgAgentUsage::new(PgPool)` implements `app::AgentUsageRepo`; `PgMatchDecisions::new(PgPool)` implements `app::MatchDecisionRepo`. Errors and rows breaking an invariant become `app::RepoError::Unavailable`. Nothing here writes `offer_matches`.
- `brightdata_runs::access_outcomes_for_run(run_id)`: the `(host, outcome)` access events of one run, for per-retailer job outcomes.
- `build.rs` reruns the build when `migrations/` changes, so `sqlx::migrate!` embeds new files.
- Binary `migrate`: applies migrations to `DATABASE_URL` (`cargo run -p db --bin migrate`). Safe to run repeatedly. Errors are logged through the URL's redactor.
- Binary `seed_e2e` (web end-to-end tests only; **never run it against a real database**, it creates an account with a known password). It refuses to start unless the `DATABASE_URL` host is `localhost`, `127.0.0.1` or `::1`; set `E2E_ALLOW_REMOTE_DB=true` to seed a non-local (or Unix-socket) test database:
  - `seed`: creates or resets the account `E2E_EMAIL` (default `e2e@example.com`) with password `E2E_PASSWORD` (default `e2e-password-123`, at least 8 characters): plan `free`, a Costco membership only, locale `es`, onboarded. It also writes accepted matches of `liverpool/E2E-LIV-1`, `walmart_mx/E2E-WAL-1` and `costco_mx/E2E-COS-1` to ASIN `B0E2ETEST1`, plus 400 days of daily observations for listings with no history yet (observations are append-only). It also creates or resets `E2E_PENDING_EMAIL` (default `e2e-pending@example.com`, same password, locale `es`, plan `free`) with no memberships and `onboarded=false`. Idempotent.
  - `complete [--watch]`: fills every queued or running search of that account with fixed results (including a `sams_mx` result that needs a membership the account lacks) and marks it `done`; `--watch` repeats every 500 ms. This replaces the worker in the e2e tests. The `costco_mx/E2E-COS-1` result is left `needs_review` (constants `REVIEW_RETAILER`/`REVIEW_SKU`); the scripted assistant model of the e2e suite proposes a decision for exactly that listing, so keep them in sync.
  - `reset-assistant`: deletes both e2e accounts' `match_decisions`, `match_suggestions` and `agent_token_usage` rows in one transaction, so the `needs_review` fixture is back (the assistant e2e spec runs it before and after; `seed` runs it too).

- Binary `seed_demo` (local demos only; [demo-data](db/demo-data.md)): orchestrates `demo::history`, `demo::account` and `demo::searches`, warns when the kill switch would refuse the searches, and logs a summary. Idempotent; it refuses a non-local `DATABASE_URL` (`require_local`, no opt-in) and never changes `safety_settings`.
- `local_guard`: `is_local_target(&DatabaseUrl)` (TCP host `localhost`, `127.0.0.1` or `::1`; a Unix socket is not local), `check_target(url, allow_remote)` (`seed_e2e`: the `E2E_ALLOW_REMOTE_DB=true` opt-in) and `require_local(url)` (no opt-in: `seed_demo` and the worker's demo mode). Errors name variables only, never the URL.
- `demo` (local demos only; details in [demo-data](db/demo-data.md)):
  - `catalog`: `DemoCatalog::embedded()` parses and validates `config/demo_catalog.json` (embedded at build time); `groups`, `group_products(group)`, `listings()`; listing `availability: ListingStock`. Errors (`DemoCatalogError`) name the product key or group. Shared with the worker's `demo` module.
  - `history`: pure `daily_points(base, salt, today_day, days, sold_out)` (seasonal model), `hot_sale(year)`, `buen_fin(year)`, `civil_from_days`, `days_from_civil`, `weekday`, `salt`; `seed_history(pool, catalog, now_ms) -> HistoryReport { written, kept }` writes it for listings without history.
  - `account`: `DEMO_EMAIL`, `DEMO_PASSWORD`, `DEMO_MEMBERSHIPS` (Costco only), `upsert_demo_account(pool, now_ms) -> UserRow`.
  - `searches`: `groups_to_queue` (pure), `existing_queries(pool, tenant)` (not `failed`/`refused`), `queue_group_searches(pool, tenant, catalog, now_ms) -> QueueReport { queued, kept }` through `app::StartSearch` over `PgSearches`.

## Dependencies

- Workspace: `domain`, `app` (port traits it implements), `secrets` (`Secret`, `Redactor` for `DATABASE_URL`).
- External: `sqlx` (Postgres, rustls), `thiserror`, `tokio`, `tracing`, `anyhow`.
- Tests: `crates/db/tests/brightdata_runs.rs`, `crates/db/tests/price_history.rs` and `crates/db/tests/jobs.rs` (queues, atomic search enqueue, tenant-scoped reads, tracking, the usage-cap race and the kill switch) `crates/db/tests/users.rs` (accounts, duplicate e-mails, sessions and expiry, the new search-result columns) and `crates/db/tests/assistant.rs` (token usage adds without lost updates, tenant-scoped suggestions and decisions, the cross-tenant suggestion foreign key, `offer_matches` untouched, recent results) need Postgres, so they are ignored by default; run `cargo test -p db --test <name> -- --ignored` with `DATABASE_URL` set (CI runs all five in the `migrations` job). The price-history tests cannot delete their rows (append-only), so each uses a unique SKU.

## Owned tables

All tables. Currently:

- `app_meta(key, value)`: baseline key/value metadata (migration `0001_init.sql`).
- `safety_settings(id = 1, global_kill_switch, brightdata_enabled, updated_at)`: one row, seeded with both off, so the Bright Data connector starts disabled (migration `0002_brightdata_runs.sql`).
- `brightdata_runs(id, tenant_id, job, mode, input_json, snapshot_id, status, requested_count, row_count, failed_count, error_message, created_at, updated_at)`: durable Bright Data runs (migration `0002_brightdata_runs.sql`). CHECKs: tenant/job `[A-Za-z0-9_.:-]{1,100}`, mode `unlocker|dataset`, status `starting|running|ready|imported|failed|cancelled|blocked_needs_kyc` (the last added by `0003_blocked_needs_kyc.sql`), snapshot id `[A-Za-z0-9_-]{1,200}`, counts ≥ 0, error ≤ 1000 characters, input ≤ 32 KiB. The partial unique index `brightdata_runs_one_active` allows one active run per (tenant, job); indexes on `(tenant_id, created_at)` and `status`.
- `brightdata_access_events(id, run_id, host, outcome, created_at)`: one row per URL attempt, host only (migration `0003_blocked_needs_kyc.sql`). `run_id` references `brightdata_runs` (cascade); outcome CHECK `ok|blocked_needs_kyc|skipped_robots|failed`; index on `(host, outcome)`.
- `offer_matches(retailer, retailer_sku, asin, method, confidence_bp, status, matched_at)`: one Amazon match per retailer listing, primary key `(retailer, retailer_sku)` (migration `0004_matching_price_history.sql`). CHECKs mirror the domain: retailer `^[a-z0-9_]{1,40}$`, SKU 1–100 characters, ASIN `^[A-Z0-9]{10}$`, method `gtin|title`, confidence 0–10000 bp, status `accepted|needs_review|rejected`. Indexes on `(asin, status)` and a partial index on `matched_at WHERE status = 'needs_review'` (the review queue).
- `price_observations(id, retailer, retailer_sku, price_mxn, list_price_mxn, availability, observed_at)`: every observed retailer price (migration `0004_matching_price_history.sql`). Money is `BIGINT` centavos (`price_mxn ≥ 0`, `list_price_mxn` NULL or above the price); availability `in_stock|out_of_stock|pre_order|unknown`. Index `(retailer, retailer_sku, observed_at)` for per-product time ranges. **Append-only**: the function `price_observations_append_only()` raises on UPDATE/DELETE (row trigger) and TRUNCATE (statement trigger). Retention: kept indefinitely; pruning needs a new migration and an ADR.
- `pgmq` schema (migration `0005_pgmq.sql`): pgmq v1.10.0 SQL vendored verbatim (PostgreSQL license; source and tag in the file header), so the stock Postgres image needs no extension. Never edit it; upgrades go in a new migration. The queues `search_jobs`, `search_jobs_dlq`, `refresh_jobs` and `refresh_jobs_dlq` (tables `pgmq.q_<name>` / `pgmq.a_<name>`) are created by `0006_jobs.sql`.
- `searches(id, tenant_id, query, status, reason, created_at, updated_at, finished_at)` (migration `0006_jobs.sql`): one background search. CHECKs: tenant `[A-Za-z0-9_.:-]{1,100}`, query 1–100 characters, status `queued|running|done|partial|failed|refused`, reason ≤ 200 characters.
- `search_retailers(search_id, retailer, outcome, offers)`: per-retailer outcome, primary key `(search_id, retailer)`, cascade from `searches`; outcome `ok|category_only|blocked_needs_kyc|skipped_robots|failed|no_offers`.
- `search_results(search_id, retailer, retailer_sku, title, url, price_mxn, asin, match_status, confidence_bp, amazon_price_mxn, fees_mxn, profit_centavos, roi_bp, margin_bp, availability, membership_required)`: priced offers of a search, primary key `(search_id, retailer, retailer_sku)`, cascade from `searches`. Money in centavos, ratios in bp; the Amazon columns are NULL without a match. `availability` (`in_stock|out_of_stock|pre_order|unknown`, default `unknown`) and `membership_required` (default false) were added by `0008_users_sessions.sql`.
- `tracked_products(retailer, retailer_sku, tracked_at, last_refreshed_at, last_attempted_at)`: listings the refresh schedule keeps current, primary key `(retailer, retailer_sku)`. `last_attempted_at` (0007) is set for every SKU of a refresh batch, success or not; the due order is `COALESCE(last_attempted_at, last_refreshed_at)` never-tried first, so failing listings rotate behind the others (indexed).
- `provider_usage(tenant_id, provider, day, requests)`: paid Amazon requests per tenant per UTC day, primary key `(tenant_id, provider, day)`; provider `amazon`, requests ≥ 0.
- `users(id, email, password_hash, tenant_id, plan, has_costco, has_sams, onboarded, locale, created_at, updated_at)` (migration `0008_users_sessions.sql`): accounts. `email` is unique and lowercase (3–254 characters); `tenant_id` is a generated column `'user-' || id` (unique), so no client can choose it; plan `free|pro`; locale `es|en`; `password_hash` is a PHC string ≤ 512 characters.
- `sessions(id, data, expires_at)` (migration `0008_users_sessions.sql`): server-side web sessions; `id` 1–64 characters, `data` ≤ 64 KiB of bytes serialized by `api`; index on `expires_at`.
- `agent_token_usage(tenant_id, day, input_tokens, output_tokens)` (migration `0009_assistant.sql`): assistant tokens per tenant per UTC day, primary key `(tenant_id, day)`; counts ≥ 0.
- `match_suggestions(id, tenant_id, chat_id, retailer, retailer_sku, asin, title, decision, reason, created_at)` (migration `0009_assistant.sql`): a verdict the assistant proposed for one of the tenant's `needs_review` listings; never applied on its own. CHECKs: chat id `^[A-Za-z0-9-]{8,64}$`, retailer/SKU/ASIN as in `offer_matches`, title 1–500, decision `accept|reject`, reason 1–300 characters. `UNIQUE (id, tenant_id)` for the decisions foreign key; index `(tenant_id, chat_id, id)`.
- `match_decisions(tenant_id, retailer, retailer_sku, asin, decision, decided_by_user_id, suggestion_id, decided_at)` (migration `0009_assistant.sql`): a user's verdict on a listing's match, scoped to their tenant, primary key `(tenant_id, retailer, retailer_sku)` (a new verdict replaces the old). `decided_by_user_id` references `users` (cascade); `(suggestion_id, tenant_id)` references `match_suggestions (id, tenant_id)`, so only the tenant's own suggestion can be confirmed. Index `(tenant_id, asin)`. It overlays only that tenant's search results and price stats; `offer_matches` stays global and unchanged.
- `_sqlx_migrations`: sqlx migration history (managed by sqlx).
